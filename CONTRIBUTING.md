# Contributing to NetGent

> *"Look, we're not creating bank software or landing rovers on Mars here. But let's not write shit code either."*  
> — **zidanaetrna**

First of all: welcome! If you're here, it means you also suffered through dragging cables in Cisco Packet Tracer at ungodly hours, and you want to make automated networking even better.

Whether you're fixing a typo, adding a new router chassis model, or making the CLI output even snappier, we want your code. Here are some simple, common-sense rules so we can all stay friends.

---

## The Golden Rules of NetGent

1. **Don't Write Spaghetti**:
   - Write code that humans can read without needing an aspirin.
   - If a function is longer than 50 lines and does 8 unrelated things, break it up. You're not being charged per function definition.
2. **Descriptive Names Only**:
   - Bad: `d`, `tmp2`, `calc_thing()`, `stuff_list`.
   - Good: `device_coords`, `target_ip`, `calculate_canvas_offset()`.
   - If your variable name looks like a password generated by a cat walking on a keyboard, rename it.
3. **Zero Hardcoded Personal Paths**:
   - Don't hardcode `C:\Users\your_username\Downloads\something`. We don't have your hard drive.
   - Use `PROJECT_ROOT`, relative paths, or environment variables.
4. **Respect the Mouse**:
   - The primary philosophy of NetGent's IPC engine is **zero mouse hijacking**. If an action can be performed via the Socket.IO programmatic bridge, do NOT use `pyautogui` clicks. Users want to keep browsing memes while their network deploys.
5. **Keep Tests Green**:
   - We maintain a comprehensive test suite with a 100% pass rate. If your PR breaks tests, don't just delete them and pretend nothing happened. Fix the code.

## Local Setup (Takes 2 Minutes)

1. **Fork and Clone**:
   ```bash
   git clone https://github.com/zidanaetrna/netgent.git
   cd netgent
   ```

2. **Spin up a Virtual Environment**:
   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # Linux/macOS:
   source .venv/bin/activate
   ```

3. **Install Dependencies**:
   ```bash
   pip install -r requirements.txt
   pip install -e .
   ```

4. **Run the Test Suite (Sanity Check)**:
   ```bash
   python -m unittest discover tests
   ```
   If it says `Ran XX tests in XX.XXs - OK`, you're golden.

## Contributing a New Topology Recipe

Got an awesome topology from your university lab, CCNA certification prep, or work? Add it!

1. Place your recipe under `topologies/<your_cool_topology>.yaml`.
2. Follow the standard declarative schema:
   - `name` & `description`
   - `devices` with normalized coordinates `(x: 0.0-1.0, y: 0.0-1.0)`
   - `connections` with explicit interfaces (e.g. `GigabitEthernet0/0`)
   - `configurations` with IOS command sequences or PC IP settings
   - `verifications` with `source`, `target_ip`, and `ping_count`
3. Test your recipe with dry-run:
   ```bash
   python src/main.py --recipe topologies/<your_cool_topology>.yaml --dry-run
   ```

## Submitting Your Pull Request

1. Create a branch that actually describes what you did:
   ```bash
   git checkout -b feat/support-cisco-3850-switch
   ```
   *(Please don't name your branch `patch-1` or `update-code`)*.
2. Commit with meaningful messages:
   ```bash
   git commit -m "feat(ipc): add port mapping for Cisco 3850 Catalyst switch"
   ```
3. Run the tests one last time:
   ```bash
   python -m unittest discover tests
   ```
4. Push and open your PR on GitHub! We will review it, laugh at your jokes, and merge it with gratitude.
